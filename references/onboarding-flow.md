# 小虾销售系统 · 初始化引导流程

## 前置条件
- config.json: `_status: "setup"`, 所有用户字段为空
- data/: 所有json文件归零
- cron: 全部暂停
- 旧沙盒数据归档在 `data/backups/archive_YYYYMMDD/`

## 引导步骤

### 阶段A：收集信息（一问一答）

**第1步：称呼**
- 系统在报告中引用用户时使用的名字
- 给出方向参考（平时和客户沟通用的名字、中文名等），等用户说出具体值
- 写入 `config.json → owner_name`

**第2步：时区**
- 给出常见选项（北京时间UTC+8、迪拜UTC+4、欧洲中部UTC+1、美东UTC-5）
- 等用户选择
- 写入 `config.json → owner_timezone`

**第3步：WhatsApp号码**
- 格式不含+号，如 `8618530726580`
- 等用户给出
- 写入 `config.json → owner_phone`

### 阶段B：自动执行（不问"继续吗？"）

> ⚠️ **关键规则：三步信息收集完成后，以下所有步骤连续自动执行。**
> 每步只报告结果，不问"继续吗？""要执行吗？"。用户已经在前三步给出了"启动"信号。
> 只有遇到需要用户操作的阻塞（如扫码认证）才停下来。

**第4步：wacli认证**
- 跑 `wacli auth status --account test`
- 已认证 → 报告"已认证"并继续
- 未认证 → 停下来，引导用户扫码。完成后继续。

**第5步：首次同步**
- 跑 `wacli sync --once --account test --max-db-size 500MB`
- 报告同步结果和新增消息数
- 自动继续

**第6步：首次数据提取**
- 跑 `python3 extract.py`
- 显示客户数、池子分布
- 自动继续

**第7步：启用定时任务（按顺序，连续执行）**
1. 启用 wacli同步cron (每2h:00)
2. 创建 extract刷新cron (每2h:01, no_agent=true, script=crane_extract.sh)
3. 启用 每日报告cron (09:00)
- 全部启用后一次性报告cron状态

**第8步：激活系统并出初始化报告**
- 修改 `config.json → _status: "active"`
- 一次性展示：
  - ✅ 用户信息确认
  - 📊 当前数据概览
  - ⏰ 自动化运行清单
  - 📅 首次报告时间

## 硬规则

- **阶段A：一问一答，不替用户填值。** 每个用户字段必须由用户说出。不假设"memory里有的号码""上次用过的名字"。
- **阶段B：连续执行，不问"继续吗？"。** 用户已在阶段A给了启动信号。每步只报结果不请求许可。报完自动下一步。
- **遇到阻塞才停。** 只有需要用户动作的事（扫码、填token）才中断流程。技术操作全自动。
- **最后一次性报告。** 所有步骤完成后给一个"系统已启动"的汇总，而不是每步一条零散消息。
